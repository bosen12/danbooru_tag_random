# Sports Consistency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve manual pins and eliminate sport-tag compatibility, validity, and hand-usage contradictions while keeping heat-driven activity as the default.

**Architecture:** `web/sports.js` owns preset definitions, explicit tag scopes, venue compatibility, and verifier inventory. `web/engine.js` owns pure state transitions and draw-time physical constraints; `web/boot.js` persists preset provenance and exposes the activity-pin toggle.

**Tech Stack:** Browser ES modules, JSON lexicon generated by Python, Node assertion script, localStorage, Danbooru JSON API.

## Global Constraints

- Existing explicit conflicting pins must be preserved and warned, never silently removed.
- Legacy saves must not infer ownership or delete data.
- New Danbooru tags must be valid; model-age checks are warnings with a configurable year.
- Tests are written and observed failing before production changes.
