# 卡片群組（墨池）設計

2026-11-16。專案主提出：長相、服裝、姿勢、場景各自可以建好幾個群組（A、B、C），抽牌時每個類別選要從哪幾組抽。

## 專案主已決定

1. 群組是**候選池**：照「每段抽幾個」的數量，從群組裡抽；不是整組全部帶上（那是現有「牌組」的套用）。
2. 群組**沒放到的小類照常從整個詞庫補**；群組只管它有放牌的那些小類。
3. 一個類別勾好幾組時，**兩種抽法都要能選**：
   - 整組一起：每張圖隨機挑其中一組，這張的這個類別只用這一組（人設不被拆散）。
   - 混著抽：勾到的組合成一個池子。
4. 入口在墨池左欄「每段抽幾個」四個數字旁邊。

## 我替他決定的（設計師判斷，送審）

### 資料

- 群組：`{ id, name, section, tags[], createdAt }`；`section` 是 `feature | pose | clothing | env`。
  只收那一段的詞庫牌（自製牌第一版不收：它是好幾張牌加詞庫外的字，不是單一段落的一張牌）。每組上限 120 張，總數上限 200 組，名字 40 字。
- 存在伺服器 `data/card_groups.json`，新模組 `card_groups.py`（照 `card_decks.py` 的寫法：file_lock、讀不懂先試 .bak、
  詞庫改名照 `card_usage.rename` 換新名）。路由 `GET/POST /api/card-groups`、`DELETE /api/card-groups/<id>`。
  手機、電腦共用。測試伺服器用 `CARD_GROUPS_PATH` 隔離（launch.json 的 web6-test 補上）。
- 「哪一段勾了哪幾組、用哪種抽法」是抽牌設定的一部分，存在墨池的 settings（跟「每段抽幾個」同一處）：
  `settings.groups = { feature: { ids: [...], mode: "whole" | "mix" }, ... }`。刪掉的群組 id 讀取時自動濾掉。

### 抽牌（引擎）

- 墨池在叫引擎之前，把勾選解析成**每一段一份 tag 清單**：`settings.groupPools = { feature: ["blonde hair", ...], ... }`。
  - 混著抽：所有勾到的組取聯集。
  - 整組一起：用這張圖的種子派生一顆獨立亂數（`mulberry32(seed ^ 常數)`）挑一組。用獨立亂數，主亂數一次都不多吃，
    所以**沒勾群組時，同一顆種子抽出來跟以前一個字都不差**。
  - 一併傳 `settings.groupNames = { feature: "金髮雙馬尾" }`（整組一起時挑中的那組）給出處標示用。
  - 引擎只認 `groupPools`，不知道「群組」這個概念 → MCP、Discord、worker 不必懂群組，之後要開放只要傳清單。
- 引擎的閘門下在 commit（跟現有「不補」「骨架選格」同一道 `innerCommit`）：
  只擋引擎自己要補的（`random`、`era_anchor`），**不擋** `repair`（分級需要的最低限度衣服等安全修補）、釘選、必抽、
  相依字（implies／bind）、合成池的牌。
  - 一張候選牌 `it`，它的小類 `supplementKindKeys(it)`；如果那段的 groupPools 在這個小類**有牌、而且其中至少一張
    此刻還抽得到**（`allow()` 過、沒被用掉、互斥沒被佔），而 `it` 不在 groupPools 裡 → 擋下。
  - 群組在這個小類的牌全都抽不到（被尺度、分級、時代、性別、封鎖、互斥擋掉）→ 不擋，照常補。
  - `takeFromPool` 被擋會換下一張，所以結果等於「這一格只從群組裡挑」。
- 出處：從群組抽到的牌，trace 的 source 記成新的 `SOURCES.group`（附 `groupNames` 裡的組名），牌的出處標示顯示
  「來自群組 金髮雙馬尾」。
- 「同一個人」＋整組一起：同一輪第 2 張起，長相沿用第 1 張挑中的那組（網頁強制，不是靠身分鎖碰巧對上）；服裝、姿勢、場景每張照樣重挑。

- **群組先上**（實作時改的）：只靠閘門不夠：詞庫先抽到的牌會讓群組的牌變不合法（髮長先抽到短髮，群組的雙馬尾
  就被擋，整格退回詞庫，測試實測漏 8 種髮型）。所以在骨架格之前，群組有放牌的每個小類先從群組挑一張
  （每段最多「每段抽幾個」張、有角色時長相交給角色、種子派生的獨立亂數），後面的格子像配合釘選一樣配合它。
  通用補牌 `fill()` 也先從群組抽，抽不滿才輪到詞庫。

### 看全部群組：做進卡冊（2026-11-16 專案主要「看得到所有群組的地方，好看、好用、方便」，交給我決定）

卡冊本來就是「看所有牌」的房間：牌面、搜尋、花色篩選、FLIP 滑位、詳情動畫都在。群組就是「一疊牌」，放進卡冊最順。
- 卡冊篩選列上方多一排**群組書籤**：照段落分（長相｜服裝｜姿勢｜場景），每組一張小書籤（組名＋張數＋前三張牌的縮圖疊）。
  點一張：卡冊收成那組的牌（照舊的 FLIP 滑位），頂部出現那組的標頭：組名（點了可改）、張數、
  「在墨池用這組」（把墨池那一段勾成這組再換過去）、「加牌」、刪除（可復原）。再點一次回到全部。
- **加牌模式**：卡冊顯示那一段的所有牌，點一下蓋章加入、再點拿掉（章蓋下去的動畫＋音效沿用卡冊的），
  頂部即時跳張數；搜尋照常可用。完成就回到群組。
- **牌的詳情**多一列「群組」：這張牌那一段的所有群組，一顆一顆小膠囊，亮的是已經在裡面，點了加入／拿掉。
- 「＋ 新群組」在書籤列尾端：選段落、取名，直接進加牌模式。
- 墨池的群組小面板只做「勾選＋抽法」和「把合成池這段的牌存成群組」，編輯一律「到卡冊編輯」—— 墨池不另做挑牌模式
  （跟偏好卡牌托盤的挑牌會打架，也省一套重複的介面）。

### 介面（墨池左欄）

- 「每段抽幾個」每一列：`長相  [−] 5 [+]` 後面多一顆小膠囊按鈕：沒勾是淡的「群組」，勾了顯示組名（兩組以上「A、B」，
  太長省略成「A 等 3 組」），亮琥珀色。
- 點膠囊打開那一段的群組面板（桌機是錨在按鈕旁的浮層，手機是底部抽屜；照 ui.js 的 openSheet 慣例）：
  - 列出這段的群組，一列一組：勾選框、組名、張數、幾張小卡預覽（前 6 張的字）、編輯、刪除（可復原，toast）。
  - 勾兩組以上時出現分段選項「整組一起｜混著抽」（滑塊，沿用負面提示詞那套動態）。
  - 只標「設定上一定抽不到」的牌（分級、性別、時代）；抽牌途中才決定的（互斥、場景）不先保證。
  - 底部「把合成池裡的長相牌存成群組」（合成池有這段的牌才出現）和「到卡冊編輯群組」。
  - 沒有任何群組時：一句說明＋「到卡冊建立群組」。
- 動態要有電影感（專案主的標準）：膠囊勾選時組名滑入、面板展開、牌飛進浮動列、勾選時預覽小卡依序浮起、
  減少動態時全部直接換。

### 不做（第一版）

- MCP `draw_prompt`、Discord、疊印台的群組選擇。引擎介面已經是 `groupPools`，之後要加只要傳清單。
- 群組權重（某張比較常出）。
- 跨段的群組（一組同時放長相和服裝）。

## 測試

- `scripts/test_card_groups.py`：存讀、上限、改名、刪除、壞檔。
- 引擎：沒有 groupPools 時逐種子比對結果不變；有 groupPools 時被覆蓋的小類只出群組的牌；群組那格全被擋時照常補；
  repair、釘選、相依字不受影響；整組一起每張只用一組、混著抽會跨組。
- 墨池介面：無頭瀏覽器走建立群組、勾選、抽牌、出處標示（電腦、手機、英文），只連 8897，擋 /api/gen。
- 英文版 `web6/locales/en.js` 補齊；同步開源版。
